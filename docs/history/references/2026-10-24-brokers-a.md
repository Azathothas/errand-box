## What this sweep did NOT establish

- **Nothing was run.** Every claim comes from reading the source at the
  captured commit. No reference was built, tested or started.
- **kage was not read.** Whether kage honours `HTTPS_PROXY` with userinfo,
  `SSL_CERT_FILE`, or a second header is unknown. That decides whether
  agent-vault's session token can reach kage's provider calls at all.
- **No Incus measurement.** What `SO_PEERCRED` and `/proc/<pid>/exe` report
  to a host daemon for a peer in an idmapped Incus guest was not measured.
- **The licence section is the common reading of the AGPL, not legal advice.**
- **Discussions were not fetched** for any of the three (GraphQL only, per
  each `PROVENANCE.md`). Tracker comments were read only for the items this
  page names.
- **Not read:** agent-vault's web UI, SDKs, OAuth, Infisical dynamic secrets
  and Docker isolation mode; claw-wrap's PTY path and its credential backends
  other than `file:` and `github-app`; wardgate's IMAP, SMTP and conclaves.
- **This page has no earlier revision**, so there is no error rate to quote.
  Assume more errors remain.

## The claims I am least sure of

Read these before the recommendations.

1. wardgate forwards the agent's own wardgate key to the upstream for an
   endpoint with `auth.type: header` and a header other than `Authorization`.
   Read from `internal/proxy/http.go:199-217`: the Director sets one header
   and deletes nothing, and Go's `httputil.ReverseProxy` keeps
   `Authorization`. Not run.
2. wardgate's `api_keys` filter misses Anthropic keys and OpenAI project
   keys. Read from the regex at `internal/filter/patterns.go:28-39`: the
   `sk-` branch needs 20 alphanumerics after `sk-`, and those keys have a
   hyphen after three or four characters. Not run.
3. wardgate's per-event SSE filter cannot see a secret that a model streams
   across several events. This is an inference from `internal/proxy/sse.go:22-69`
   and from the shape of LLM streams. Not measured.
4. wardgate accepts a JWT with no `exp`: `internal/auth/middleware.go:88-100`
   omits golang-jwt v5's `WithExpirationRequired`. The library rule is memory.
5. agent-vault keeps serving an open CONNECT tunnel after its session is
   revoked. Read from `internal/mitm/connect.go:83` and `:136`: the scope is
   resolved once per tunnel and captured. In errand-box the instance stop at
   session end closes the tunnel anyway, so this matters only mid-session.
6. claw-wrap's GitHub App example uses `owner/repo` (`README.md:120-121`);
   `docs/CONFIG.md:822` says names. GitHub's accepted form was not checked.

## agent-vault (Infisical), `d5836ec3bb23`

### Pass 1: what it is

A Go server and CLI in one binary (36542 lines of non-test Go outside
`web/`, by `find -name '*.go' -not -name '*_test.go' | xargs wc -l`). It
keeps credentials in SQLite or Postgres under AES-256-GCM
(`docs/learn/security.mdx:25-45`). It serves an API and web UI on 14321 and
a MITM forward proxy on 14322, both TCP (`internal/server/server.go:1075`,
`:1126`). The agent uses `HTTPS_PROXY=http://<token>:<vault>@host:port` and
trusts the root CA through six variables such as `SSL_CERT_FILE`
(`internal/isolation/env.go:42-62`). The README places it on a separate
machine from the agents (`README.md:63`). PostHog telemetry is on by default
and carries the user's email
(`docs/self-hosting/environment-variables.mdx:77-83`).

### Pass 2: the construction

| mechanism | where | what it does |
| --- | --- | --- |
| session token | `internal/brokercore/proxyauth.go:31-70` | Bearer, or Basic with `token:vault`, from `Proxy-Authorization`. That header is hop-by-hop, so it never reaches the upstream (`docs/learn/security.mdx:112`). |
| per-session identity | `internal/server/handle_sessions.go:134-161`, `internal/server/server.go:1390-1392` | `POST /v1/sessions` mints a vault-scoped token, TTL 5 minutes to 7 days, default 24 hours. |
| storage and revocation | `internal/store/sql_store.go:27-30`, `:1604-1622`; `handle_sessions.go:240-273` | Only the SHA-256 of the token is stored. Revocation deletes the row. Every CONNECT and every plain-HTTP request looks the token up again (`internal/brokercore/session.go:144-158`). |
| TLS interception | `internal/mitm/connect.go:107-121` | Every authenticated CONNECT is terminated with a leaf minted for the SNI, offering `http/1.1` only. The upstream transport also stays on HTTP/1.1 (`internal/mitm/proxy.go:86`). No CONNECT passes through untouched. |
| injection | `internal/brokercore/credential.go:112-253` | Matches host, port and path glob (`internal/broker/broker.go:555-650`). It never matches a method: `Service` has no method field (`broker.go:30-38`). An unmatched host is forwarded unless the vault is set to deny (`credential.go:145-154`). | SSRF | `internal/netguard/netguard.go:140-215` | Checks each address the dialer is about to connect to, after resolution, in `ControlContext`. It unmaps IPv4-in-IPv6 (`:210`) and always blocks cloud metadata (`:96-99`). |
| audit | `internal/requestlog/sink.go:21-39`, `internal/store/039_request_logs.go:11-26` | Vault, actor, method, host, path, matched service, credential key names, status, latency, error code. No bodies, headers or queries. No session id. |
| approval | `docs/learn/proposals.mdx:6-30` | An agent proposes new services or credentials; a human approves through a web link. This changes configuration. It does not gate a single request. |

### Pass 3: in an errand-box guest with no network device

- **The server side runs as a host daemon.** Bound to 127.0.0.1, its MITM
  port is a TCP target that the T-020 relay could reach through the shim's
  existing unix-to-TCP relay. errand-box would mint a scoped session per
  errand session, write the proxy URL into `/run/errand-box/env.sh`, and
  revoke the session at stop.
- **The client side needs the CA in the guest.** Docker and apt read the
  system store, not `SSL_CERT_FILE`, so the image or the boot step would need
  `update-ca-certificates`. Every TLS connection the guest makes would then
  be decrypted on the host. Today errand's broker tunnels a non-provider
  CONNECT without reading it (errand#44 quotes this).
- **HTTP/2-only and gRPC clients fail** behind an `http/1.1`-only terminator.
  This is read, not measured.
- **T-022 is out of reach:** a CONNECT to port 22 is TLS-terminated like any
  other.
- **The token still sits in the guest,** in `HTTPS_PROXY` and
  `AGENT_VAULT_TOKEN` (`internal/isolation/env.go:44-60`, `:92-95`). Unlike
  errand's nonce, it is per session, expires, and is revoked by a row delete.

### The tracker

458 items, 53 issues and 405 pull requests (jq on `pull_request`). Read:

- **#323 and PR #324, open: method restriction.** The PR also strips
  `X-HTTP-Method-Override`, `X-Method-Override`, `X-HTTP-Method` and `_method`
  on restricted services. A bot review found that `%5Fmethod` passes the
  strip. Not merged at the captured commit. Evidence of intent: method
  scoping needs override stripping, and the strip must decode before it
  compares.
- **#258 and PR #304, open: response redaction.** The PR is opt-in and fails
  closed with 502 for encoded, streamed or oversized bodies. It therefore
  cannot scrub an SSE answer, which is the case errand#46 needs.
- **#362, open.** The cause is in the corrections table. The empty error
  code is lens #57's "audited as success" in another project.
- **#381, #424 and #192, open.** CONNECT rate-limit denials leave no log
  line and no row. Portable evidence has no answer. Per-request approval has
  no design.

### Candidate verdicts, each tested to refute

| candidate | result |
| --- | --- |
| wholesale replacement as a supervised host daemon | refuted by pass 3 and the table: CA in every guest, HTTP/1.1 only, no raw TCP, no response scrub, no method scope, no actor for scoped sessions, telemetry on by default |
| adopt the session token (errand#45, #49) | survives, with three caveats: the token stays in the guest environment; kage's proxy behaviour is unknown; an open tunnel keeps its scope |
| adopt the dial-time address check (T-022) | survives; see "Mechanisms worth taking" |
| anti-pattern exhibit (#362's cause, the actor gap) | true, but kept as findings under the adopt verdict |

**Verdict: adopt.** Take `netguard.go:185-215` into T-022. Take the token
design into the broker work that replaces errand's, with the actor gap fixed:
carry the session's public id to the log and the rate-limit key.

## claw-wrap (dedene), `bc66b0357675`

### Pass 1: what it is

A Go daemon and a wrapper binary (10787 lines of non-test Go). The sandbox's
`gh` is a symlink to the wrapper. The wrapper signs a request with an HMAC
secret, sends it over a unix socket, and the daemon runs the real tool on its
own side with the credential in the tool's environment
(`README.md:42-67`). A second mode is a MITM HTTP proxy on 127.0.0.1 that
injects headers by route (`internal/httpproxy/proxy.go:139-189`). Credentials
come from pass, 1Password, Bitwarden, age, Vault, a `file:` path or an
exec-json helper, and a `github-app` type mints installation tokens
(`README.md:90-124`).

### Pass 2: the construction

| mechanism | where | what it does |
| --- | --- | --- |
| caller identity | `internal/daemon/daemon.go:715-757` | `SO_PEERCRED` UID must equal one configured UID. The caller's `/proc/<pid>/exe` must be on an allowlist when readable. Across PID namespaces it falls back to UID plus HMAC and logs this once (`:750-756`, `docs/KUBERNETES.md:89`). |
| request authentication | `internal/auth/auth.go:23-29`; `daemon.go:896-909`; `docs/SPEC.md:28-46` | HMAC-SHA256 over timestamp, tool, args, cwd, env and nonce, within 5 s, with a replay cache keyed on UID and HMAC. One secret per daemon life, bind-mounted read-only into the sandbox (`SPEC.md:23-26`). |
| argument policy | `internal/daemon/args_policy.go:13-128` | Block patterns first, then an allowlist. `match: argv` anchors one regex per argument with exact arity (`:115-128`). PR #12 records that `match: command` joins the args with spaces and lets `call front.read --server https://evil.example` pass `^call\s+front\.read(\s\|$)`. |
| environment | `internal/daemon/executor.go:36-106`, `:340` | A denylist (`LD_*`, `GIT_PROXY_COMMAND`, `SSL_CERT_FILE` and others) and an optional `request_env` allowlist. |
| working directory | `executor.go:204-223` | The caller's cwd, unless the tool pins `working_dir`. |
| output scrub | `internal/daemon/output_redactor.go:62-160`; wired at `executor.go:539-541`, `:608` | Every injected value of 8 bytes or more is replaced in streamed stdout and stderr. Only a tail that is a proper prefix of a secret is held back (`:125-130`), so output that holds no secret prefix leaves at once. |
| secret file | `internal/credentials/file.go:20-58` | Open, then fstat the open file: regular, `perm & 0o027 == 0`, owner root or the daemon, at most 64 KiB. Re-read on every use. |
| GitHub App | `internal/credentials/githubapp.go:134-166`, `:215-300` | An RS256 JWT, then `POST /app/installations/<id>/access_tokens` with narrowed permissions and repositories. Cached until 5 minutes before expiry (`README.md:124`). |
| HTTP proxy | `internal/httpproxy/proxy.go:147-154`, `:273-415` | Refuses a non-loopback bind. Intercepts every authenticated CONNECT. The response gets header stripping only, no body scrub and no audit. |
| audit | `internal/audit/audit.go:17-29` | Opt-in JSONL per execution: tool, cwd, caller pid and exe, exit code, output bytes, optional args and output SHA-256. |

### Pass 3: in an errand-box guest with no network device

- **The transport fits T-020 exactly.** The daemon's socket and the
  read-only secret file in a per-session host directory, shared by a disk
  device, is the shape T-020 already chose. claw-wrap confirms it; it adds
  nothing to it.
- **Identity comes from the socket path, not from the peer.** Behind T-020's
  guest-side relay the host sees the relay's uid. Every guest's uid 1000 maps
  to the same errand account. So the per-session directory is the only
  per-session identity, which T-020's ruling already gives. claw-wrap's own
  guide reaches the same limit in Kubernetes (`docs/KUBERNETES.md:89-106`).
- **Running a tool host-side in the guest's workspace breaks SECURITY.md
  rule 1.** `/workspace` is written by the agent. A host-side `git` or `gh`
  in that directory reads the agent's `.git/config`; claw-wrap's guide warns
  about exactly this (`docs/KUBERNETES.md:110`). The guest path does not
  exist on the host anyway (`executor.go:204-223`). A pinned `working_dir`
  per tool cannot follow one project per session.
- **The redactor applies where errand-box relays bytes.** Today the shim
  hands errand's pipes straight to `incus exec` (`docs/design.md:54-56`).
  Scrubbing a T-021 secret from the agent's output would mean the shim reads
  the stream. **CAUTION:** a literal match misses an encoded copy. A
  multi-line ssh key inside a JSON string reaches errand with `\n` escapes,
  and base64 hides it entirely. Measure the escaped form before relying on it.

### The tracker

11 items, all pull requests; 1 issue comment and 41 review comments. PR #12
(the Kubernetes sidecar) lists what broke in a pod: the caller's cwd missing
on the daemon side, stdout loss when `Wait()` closed pipes early, and the
`match: command` bypass above. Review comments on PR #9 fixed option
injection in the Vault backend. Nothing was refused; there is no security
report.

### Candidate verdicts, each tested to refute

| candidate | result |
| --- | --- |
| wholesale replacement (broker, or exec channel beside it) | refuted: daemon-wide HMAC secret held by the agent, one allowed UID, no per-session identity, a host-side tool in an agent-chosen cwd, and an HTTP proxy with one shared token |
| adopt the redactor (T-021, errand#46) | survives, with the encoding caveat |
| adopt the secret-file check (T-021) | survives; it is the validation T-021's directory needs at grant time |
| adopt the GitHub App mint (errand#42) | survives as an idea for whoever owns the GitHub token; the `repositories` field format is unchecked |
| confirms T-020 | true; recorded above, not a verdict of its own |

**Verdict: adopt.** Take `file.go:20-58` and `output_redactor.go:112-160`
into T-021. The redactor is also the right shape for the broker's response
scrub (errand#46): it holds back less than #46's proposed `max_len - 1`.

## wardgate, `44cb71391a24`

### Pass 1: what it is

A Go gateway (12238 lines of non-test Go). The agent calls
`http://wardgate:8080/<endpoint>/<path>` with `Authorization: Bearer
<agent-key>`. wardgate checks first-match rules, can hold the request for a
human, injects the credential, and reverse-proxies to a fixed or allowlisted
upstream (`docs/architecture.md:99-140`). Adapters cover SSH, IMAP, SMTP and
exec. Credentials are its own environment variables. It listens on one TCP
address (`cmd/wardgate/main.go:404-408`). The last commit is 2026-03-11.

### Pass 2: the construction

| mechanism | where | finding |
| --- | --- | --- |
| route | `cmd/wardgate/main.go:320`; `internal/proxy/http.go:199-204` | `ServeMux` pattern `/<name>/` plus `StripPrefix`. This is a segment boundary by construction, and the mux cleans `..`. The upstream host comes from parsed config, never from the path. |
| dynamic upstream | `internal/proxy/upstream.go:17-80` | Parse, then compare scheme, host by segment, and path with a `/` boundary. Userinfo, query and fragment are refused. |
| agent identity | `internal/auth/middleware.go:53-84` | Static keys or HS256 JWT `sub`. The middleware overwrites `X-Agent-ID`. No `WithExpirationRequired` (`:88-100`). |
| upstream headers | `internal/proxy/http.go:199-217` | For `type: header` with another header name, the agent's `Authorization: Bearer <agent-key>` is not removed, and `X-Agent-ID` is forwarded too. The test of that type sends no agent header (`internal/proxy/http_test.go:113-137`), so it cannot see this. |
| policy | `internal/policy/engine.go:75-103`, `:195-236`; `internal/config/config.go:525-562` | First match, default deny. See errand#44 in the corrections table for the glob and ordering defects. |
| grants | `internal/grants/store.go:16-36`, `:115-165`; `internal/approval/admin.go:214-247` | See errand#43 in the corrections table. |
| approval | `internal/proxy/http.go:151-166`; `cmd/wardgate/main.go:353-363` | Holds the agent's HTTP request open until a human answers, 5 minutes by default. |
| response filter | `internal/proxy/http.go:296-360`; `internal/proxy/sse.go:22-69` | Regex only. A non-SSE text body is read whole with no size cap (`http.go:327`). Off unless configured. |
| SSH | `internal/ssh/client.go:32-47`; `internal/ssh/handler.go:67-161` | A host key is required: a pinned entry, a known_hosts file, or an explicit opt-out. Policy sees only `POST /exec`, not the command. The SSH handler has a filter field, but `main.go:263-271` never sets it. |
| sealed credentials | `internal/seal/seal.go:67-84` | AES-GCM over the bare value, bound to no host. Open issue #6 says so. |
| audit | `cmd/wardgate/main.go:422-482`; `internal/audit/store.go:27-40` | One zerolog line and an in-memory ring per request. The decision is guessed from the status. |

### Pass 3: in an errand-box guest with no network device

- **The server side would run as a host daemon** on loopback TCP, reachable
  through the T-020 relay.
- **The client side does not fit the guest's traffic.** wardgate is not a
  forward proxy, so Docker pulls, apt and `git` over `HTTPS_PROXY` have no
  path. kage's Anthropic client sends `x-api-key`, and wardgate demands
  `Authorization: Bearer <agent-key>`. That needs `wardgate-proxy` inside
  the guest, which puts the agent key in the guest. An OpenAI-shaped
  provider would work directly.
- **The SSH adapter is a different answer to T-021 and T-022:** the key stays
  on the host and commands travel as REST. The operator ruled for a mounted
  key and a raw-TCP relay (T-021, T-022 Decision). The host-key pin transfers
  to that ruling; the adapter does not.

### The tracker

6 items: 3 issues, 3 pull requests, 14 comments, 17 review comments. #6
(open) reports that sealed secrets are not bound to a host, so a
dynamic-upstream glob can send a decrypted secret to any matching host. The
reply is "I will look into this", with no change since. Review comments on

## Licence

errand-box's `LICENSE` is a 0BSD-style grant.

- **agent-vault and claw-wrap:** MIT. Vendoring or porting is allowed if the
  copyright and permission notice travel with the copied portion.
- **wardgate, vendored or linked:** a combined work that contains wardgate
  code is under the AGPL-3.0 when conveyed, with its complete source. The
  0BSD grant cannot cover that binary. Section 13 adds a source offer to
  network users of a modified copy, and `vendoring.md` patches in the tree.
- **wardgate as an unmodified separate binary,** fetched by pinned digest,
  supervised, and reached over HTTP: aggregation. errand-box's licence is
  unaffected. A release that ships the binary carries the AGPL text and a
  source offer.
- **Ideas** written again in errand-box's own words and code are not copies.

## Mechanisms worth taking, ranked

1. **Check the address the relay dials, after resolution, before connect**
   (agent-vault `internal/netguard/netguard.go:185-215`). T-022's relay runs
   on the host, so a granted name that resolves to loopback, link-local or
   metadata reaches the host's own services. Named internal machines need an
   explicit CIDR allowance (`:35-45`). Metadata stays blocked regardless.
2. **A streaming literal redactor that holds back only a proper prefix of a
   secret** (claw-wrap `internal/daemon/output_redactor.go:112-160`), for the
   broker's response scrub and for T-021 values errand-box relays. Mind the
   encoding caveat.
3. **A per-session broker token in `Proxy-Authorization`, hashed at rest,
   TTL-bound, looked up per request** (agent-vault `proxyauth.go:31-70`,
   `session.go:144-177`, `sql_store.go:27-30`). Put the session id in the log
   and the rate-limit key, which agent-vault does not.
4. **Validate a secret file at grant time** (claw-wrap `file.go:20-58`), for
   T-021.
5. **Require a pinned host key for every granted SSH target** (the idea of
   wardgate `internal/ssh/client.go:32-47`). For T-022, the boot step writes
   the pin beside the host alias.
