# Reference sweep: credential brokers, part B

This page records a read of vultrino, charon and lens-sandbox-core. The
question for each: does it replace or materially improve errand-box's broker,
secrets path, egress and DNS policy, audit or chat layer, at a cost errand-box
can carry? The procedure is [research.md](../../methodology/research.md)
section 3. Other write-ups dated 2026-10-24 cover the other references.

A cited path belongs to the reference named in its sentence, row or section,
relative to `references/OWNER__REPO/tree/` at the commit in the provenance
table. A path that starts with `src/` where no reference is named is
errand-box's own.

---

## What this sweep did NOT establish

- **Nothing was built or run.** No reference was compiled, tested or started.
  Every statement about behaviour comes from reading code at the captured
  commit. The test counts are grep counts of test attributes.
- **No mechanism was tried in an errand-box guest.** The fit with a guest that
  has no network device and a unix-socket link (T-020) is a reading, not a
  measurement.
- **kage's TLS stack was not checked.** Whether a TLS-intercepting proxy would
  break kage is unknown. lens #53 shows that a client with compiled-in roots
  rejects such a proxy.
- **Whether kage can send its provider key as `Authorization: Bearer`** was not
  checked. vultrino's model proxy reads only that header
  (`src/web/llm_proxy.rs:80-87`).
- **Partial reads.** vultrino has 103,238 lines in `src/`. The approval
  module, the vault, the WASM plugins and the clients of its sibling services
  were not read. lens's `proxy.rs` and `mitm.rs` hold 15,142 lines; only the
  path of lens #57 was traced. Each section names what was read.
- **No musl build** of any reference was tried. errand-box ships musl binaries.
- **Discussions** were not fetched for any reference (GraphQL only).

### The claims this page is least sure of

1. That a per-session socket can carry session identity to the broker. This is
   a design statement about T-020, not a measurement.
2. The extent of lens #57 at the captured commit. Six call sites propagate a
   failed dial with `?`. This sweep did not follow every error path to its
   last audit record.
3. That vultrino's set of encoded forms covers what kage's providers echo.
   Nothing here measured it.
4. The four corrections below hold at the captured commits, which can differ
   from the commits errand's issues were written against.

Assume more errors remain.

### The two mechanisms most worth adopting

1. **The listener is the identity** (charon). T-020 already puts one socket in a
   per-session host directory. If that socket alone names the session to the
   broker, then attribution needs no token in the guest, and revocation is the
   removal of the socket. This answers errand#49 and most of errand#45. The
   condition is that the identity survives the hop. `src/relay.rs:58-74`
   relays a socket to a TCP address, and if every session's relay names the
   same broker port, the identity is gone. The broker must listen on the
   per-session sockets, or each session needs its own relay target, or the
   relay must label the connection.
2. **Record the outcome, not the attempt** (charon, against lens #57). charon
   reserves the record before any work and writes it when the stream really
   ends. A dropped stream writes `interrupted` from `Drop`
   (`src/receipt.rs:150-162`, `:212-249`). lens writes "success" before it dials.
   errand-box's own relay drops a failed dial with no record (below). For volume,
   take vultrino's coalescing: one record per key per window, then a token
   bucket, with exact counts (`src/refusal.rs:1-21`, `:461-514`).

### Pass 3: in an errand-box guest, and as a library

- **As a service.** vultrino would run on the host. A guest would reach it
  through T-020's relay. kage would point its base URL at `/llm` and hold a
  per-session `vut_` token. That covers the provider route. It covers nothing
  else: vultrino is not a forward proxy, so Docker, apt and git need a second
  egress path. All sessions would share one listener, so identity rests on a
  bearer token that the agent can read.
- **As a library.** 459 packages in `Cargo.lock`, with tokio, axum, reqwest
  and wasmtime. errand-box has 22 packages and no async runtime. vultrino pins
  Rust 1.96.0 and errand-box pins 1.99.1, so the toolchain is not the obstacle.
  The weight is. Copying is realistic for three small parts:
  `llm_upstream_url`, which needs the `url` crate, and `derive_secret_forms`
  with `StreamScrubber`, which need `base64`, `hex`, `urlencoding` and `zeroize`.
- **A route not taken for T-021 and T-022.** The ssh plugin runs ssh on the
  host, so the key never enters the guest (`src/plugins/ssh.rs:1-37`). It
  offers no interactive session, it authenticates by password through
  `sshpass`, and it accepts a new host key by default (`:48-49`). The operator
  ruled for a key mounted in the guest. This route stays refused.

### Tracker

93 entries: 6 issues and 87 pull requests. 51 come from one human account and
the rest from bots. No entry is a security report from another account. The
confessions are in the pull request bodies:

- **#56: the first scrub fix still leaked.** A canary scan in a sibling
  project found 663 distinct hits across five surfaces. A "clean" run of
  the first fix was a false negative, because the scanner could not see the
  base64 of `Bearer <token>`. Byte scrubbing is defence in depth, and its own
  author says so (`src/egress.rs:1-15`).
- **#44:** `https://api.example.com*` matched `https://api.example.com.evil.net`.
  This is errand#48's class, fixed by canonical matching and a host boundary.
- **#92:** three mutants were "killed" vacuously, because the patch changed no
  covered symbol. The kit caught it.

### Candidate verdicts, tested

| candidate | test | result |
| --- | --- | --- |
| adopt the path containment for errand#48 | is the boundary real? Joining with `/`, the second parse and the `base_path/` prefix test close the `prefix + rest` defect of errand#48 | stands |
| adopt the stream scrubber for errand#46 | does #56 refute it? No: #56 widened the set of forms. The output check at `src/egress.rs:880-903` is the part a simpler scrubber lacks. charon's rolling redaction (`src/response.rs:86-150`) confirms the approach on its own | stands, as defence in depth only |

**Verdict: adopt.** Three mechanisms, as in the results table. All three are
small enough to copy or to write again.

## charon

### Pass 1: what it is

| | |
| --- | --- |
| shape | one crate, edition 2024, Rust 1.99. 17 files, 10,496 lines in `src/` |

### Pass 3: in an errand-box guest, and as a library

- **As a service.** Gateway mode binds one IPv4 address per workload
  (`src/gateway.rs:157`) and has no unix listener (`src/main.rs:121-130`).
  errand-box would run one charon process per session on a loopback port,
  behind the session's T-020 socket. Every guest image would trust charon's CA,
  so Docker's daemon and every client with compiled-in roots would need it too.
  Each restart of each process would wait for a manual unlock. That conflicts
  with `up` as the whole recovery after a host restart
  ([design.md](../../design.md), "Keeping the host up"). Raw TCP and ports
  other than 443 are refused (`contracts/workload-gateway.md:51-55`), so
  T-022 has no path through it. Wildcard hosts do not exist, and errand's
  default allowlist is `["*"]`.
- **As a library.** 356 packages, including rusqlite with bundled SQLite,
  `openssl-sys` through webauthn-rs, and `aws-lc-sys`. Native C code makes a
  static musl build harder. `src/receipt.rs` has 423 lines before its tests,
  over tokio and sha2. errand-box would write its own rather than link it.

### Tracker

88 entries: 2 issues and 86 pull requests, from one human account and bots.
The findings:

- **#7: an audit by the owner found two high defects.** Credentials went out in
  plain HTTP and to other ports, and a caller could choose the `Host`
  authority. Both are fixed.
- **#71: the generated CA failed strict OpenSSL verification.** The leaf had
  no authority key identifier and the CA had no key usage. The pull request
  says that a new image cannot repair a CA already installed: it must be made
  again and distributed again. lens #11 is the same defect.
- **#1, open:** an outside comment asks how a revoked approval rule finds the
  operations it already allowed. The tracker holds no answer.

### Candidate verdicts, tested

| candidate | test | result |
| --- | --- | --- |
| adopt identity by listener for T-020 and errand#49 | does T-020 meet charon's condition, a listener that only one workload reaches? The socket sits in a per-session host directory, shared into one instance. Only root and the errand account also reach it. The relay must keep the identity (see the top of this page) | stands |
| adopt the receipt for T-023 and errand#47 | T-023 requires a bound on disk. charon has none, and a rotation would break its chain unless a checkpoint carries over. Take the field set, the reservation and the close on the real end of the stream. Leave the unbounded file | stands, in part |

**Verdict: adopt.** Identity by listener into T-020, and the receipt shape
into T-023. Both are ideas, written again in errand-box's code.

## lens-sandbox-core

In this section, a path under `src/` is under `crates/lens-sandbox-core/`
unless it names another crate.

### Pass 1: what it is

| | |
| --- | --- |
| shape | a workspace of three crates. `lens-sandbox-core`: 54 files, 56,500 lines. `lens-sandbox-runtime`: 26 files, 7,906 lines. `lens-sandbox-supervisor`: 7 files, 1,108 lines. Rust 1.96.1 |

### Pass 3: in an errand-box guest, and as a library

- **The transport confirms T-020.** The runtime serves its only channel on
  `unix:/path`, "for a socket on a shared volume", and the workload needs no
  egress (`README.md:30-34`). A small hardening worth copying: the runtime
  removes a stale path only when that path is a socket
  (`crates/lens-sandbox-runtime/src/linux/listen.rs:36-39`). errand-box's
  `src/relay.rs:59` removes whatever is there. That is safe only while the
  directory stays out of the guest's reach, which T-020's ruling requires.
- **The rest does not fit.** The runtime must be PID 1 of the workload, and an
  errand-box guest runs systemd as PID 1. The cage needs nftables and
  `CAP_NET_ADMIN` in the namespace it guards.
- **As a library.** 313 packages, including tonic, hickory, nfq, landlock and
  `aws-lc-sys`. The `proxy` feature is on by default.

### Tracker

75 entries: 15 issues and 60 pull requests, from six human accounts and one
bot account. 279 review comments. The defects that matter here:

- **#57, open: audit says success, client gets a reset.** The success record is
  written while the request head is read, in `mitm_inject_after_accept`
  (`src/mitm.rs:990`, record at `:1530-1540`). The dial comes after it
  (`src/mitm.rs:235`, then `:250-259`). One door answers a failed dial with 502
  and writes an error record (`src/proxy.rs:2126-2137`). Six other call sites
  propagate the error with `?` (`src/proxy.rs:1660`, `:1726`, `:1840`, `:1876`,
  `:3235`, `:3252`). A body that fails half way is dropped in silence
  (`src/mitm.rs:589`), and the error is logged at debug (`src/proxy.rs:653`).
  No test in `src/mitm.rs` covers a failed dial.
- **#29: the two layers disagreed on "ask".** The connect gate offered "Allow
  once", but the DNS stub had already refused the name, so "Allow once" could
  never succeed. The fix is the session-long DNS set noted above: an allow-once
  at one layer became a session grant at another.
- **#10, #11 and #53: the cost of interception.** IPv6 passed around the
  interceptor (#10). The CA failed strict verification (#11). Clients with
  compiled-in roots reject the CA, and #53 is still open.
- **#50, open: a policy file written under a bind mount lands on the host.**
  The path stays inside the allowed root, but the device does not.

**Verdict: anti-pattern exhibit.** lens #57 is a shipped audit defect, and its
own test suite did not catch it. It is filed against T-022 and T-023: write the
outcome of a connection, never the attempt. The runtime's interception of
`connect()` is OpenShell's code, so the OpenShell write-up owns it (**filed
elsewhere**).

## What this changes in errand-box's plan

- **T-020.** Keep the identity through the relay (mechanism 1). Remove a stale
  socket path only when it is a socket.
- **T-021.** Measure before building: where does Incus create the mount point
  when a file disk device lands under `/state`, which is itself a host
  directory? lens #50 shows a write under a bind that reached the host. Nothing
  here measured errand-box's case. For the secrets directory, charon's file
  check (`src/keepass.rs:259-273`: no symlink, a regular file, no group or
  other bits) is the minimum. errand-box would also check that root owns it.
- **T-022.** The relay writes a record for every refused and every failed
  connection, with exact counts under a volume bound (mechanism 2).
- **T-023.** A receipt has a closed field set and never a URL, a query, a
  header or a body. It is reserved before the work and closed at the real end.
  The file needs a size bound and rotation, which charon lacks. vultrino
  derives its record budget from the settings (`src/refusal.rs:244-249`);
  T-023 can derive its disk budget the same way.
- **A broker, if errand-box carries one.** errand#48: join on `/`, parse again,
  and require the same origin and a segment-boundary prefix (vultrino
  `src/capability/mod.rs:616-668`). errand#44, placement half: forward an
  allowlist of agent headers and let the broker place the credential (vultrino
  `src/web/llm_proxy.rs:89-114`). errand#46: scrub with an output check, and
  call it defence in depth, as vultrino #56 shows. errand#43: a grant must
  expire in every layer it opens, which lens #29 shows.
- **TLS interception.** Four bugs in two projects (lens #10, #11, #53; charon
  #71) confirm the choice to terminate no TLS. A CA would live in the guest
  image, so a change to it rebuilds every host's image (E-31).

### A defect found in errand-box while reading

`src/relay.rs:62-70`: when `TcpStream::connect(&target)` fails, the accepted
unix connection is dropped. No log line and no record is written.
`src/relay.rs:79-88` has the same shape for TCP. This is the shape of lens #57.
The rootless engine's broker link (E-23) uses this relay, and T-020 and T-022
would use it. It is recorded here and not fixed, per
[research.md](../../methodology/research.md), "What a research session does
not do".
