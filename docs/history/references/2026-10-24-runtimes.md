# Reference sweep: whole agent runtimes, OpenShell and raxis

This page records a read of two projects that are whole agent runtimes:
NVIDIA's OpenShell and chika5105's raxis. The question for each one: could it
replace errand (the chat, session and broker layer), errand-box (the sandbox
and the host setup), or both, on the hosts errand-box targets? If not, which
mechanism is worth adopting, and into which entry? The procedure is
[research.md](../../methodology/research.md) section 3. The other write-ups
dated 2026-10-24 in this directory cover the other references.

Paths in code spans that start with `crates/`, `docs/`, `specs/`, `kernel/` or
`install.sh` belong to the reference that the section names. OpenShell paths
are relative to `references/NVIDIA__openshell/tree/`. raxis paths are relative
to `references/chika5105__raxis/tree/raxis/`. Paths that start with `src/`,
`TODO/` or `docs/research/` and carry no reference name are errand-box's own.
A number written `#N` is the tracker of the reference that the section names;
`errand#N` is errand's tracker.

---

## What this sweep did NOT establish

- **Nothing was built or run.** Neither reference was compiled, installed or
  started. Every statement about behaviour comes from reading code at the
  captured commit. Another agent held the build slot.
- **No host test.** Neither runtime ran on the build host or on any host of
  errand-box's matrix. The fit tables below are readings of the code against
  [edge-cases.md](../../edge-cases.md), not measurements.
- **Partial reads.** OpenShell has 651,154 lines of Rust (all lines of every
  `.rs` file, blank lines included) in 38 crates. This sweep read the sandbox
  runtime's admission probe, its seccomp and Landlock modules, the Docker and
  Podman driver checks, the upstream proxy, the raw TCP relay, the policy
  generation guard, the credential placeholder code, the endpoint path match,
  the request-target canonicalizer, the policy DNS header and the OCSF writer.
  It did not read the gateway server (178,465 lines), the OPA engine body, the
  Kubernetes, VM or Windows drivers past the lines cited, or the prover.
- raxis has 457,034 lines of Rust in 57 crates. This sweep read the isolation
  tier and its admission, the Firecracker host probe, the HTTP credential
  proxy, the credential proxy manager, the audit record format, the egress
  stall tracker and the system requirements spec. It did not read the kernel's
  IPC handlers, the planners, the database proxies past their headers, or the
  tproxy.
- **The trackers were searched by topic, not read in full.** OpenShell has
  1,717 issues and 2,738 pull requests. The topics: Docker, FUSE, systemd,
  cgroup v1, Landlock, KVM, WSL, corporate proxies, chat services and
  security reports.
- **Discussions were not fetched** for either reference (GraphQL only).
  OpenShell #4 says its isolation decision moved to #558. #558 is not in the
  corpus, so it is probably a discussion. That decision is unread.
- **raxis has no tracker to read.** Its four items are dependency bumps by a
  bot, with no comments. Its 24 releases have empty bodies. No host failure
  of raxis is on record anywhere this sweep could reach.

## The claims this page is least sure of

1. **The raxis path allowlist bypass is read, not run.** `restriction.rs`
   checks the raw path; `url` 2.5.8 then resolves `..` and `%2e%2e` segments
   in `set_path` (`src/parser.rs:1318-1327` of that crate, the version
   `Cargo.lock:5177-5180` pins). The two readings agree. No request was sent.
2. **OpenShell's Docker driver on cgroup v1.** A search of the Docker driver
   found no cgroup version check, and Docker 29.9.1 ran on the cgroup v1
   build host ([engines.md](../../research/engines.md)). Nobody ran OpenShell
   there.
3. **OpenShell #3911** (open) says `hard_requirement` started a workload with
   Landlock ABI 0 on v0.1.2. At the captured commit the admission probe calls
   `require_landlock_abi` (`crates/openshell-sandbox/src/main.rs:157-161`).
   Whether #3911 still reproduces is not established.
4. **raxis's audit chain is unsigned** in `crates/audit/src`. No other crate
   was searched for an external anchor of the chain head.
5. **raxis and an HTTP proxy.** Its spec says it reads no `HTTPS_PROXY`
   (`specs/v1/env-vars.md:227-230`), and a search found no upstream proxy
   setting. Whether its HTTP client library reads the variable anyway was not
   checked.
6. **Absence claims are search results.** "No disk quota in the Docker
   driver", "no ssh credential path in either tree" and "no upstream response
   scrub in OpenShell" each come from a search, then a read of the nearest
   file. A search locates; it does not prove absence.
7. **CONNECT to port 22.** The build host's proxy allows CONNECT only (E-10).
   Whether it allows CONNECT to port 22 is not measured, so T-022's ssh
   example can fail there whatever relay carries it.

## The question, and the hosts it was tested against

errand-box's guest gives the agent systemd as PID 1, Docker, podman, FUSE,
passwordless sudo, a btrfs disk quota and per-session limits, with no network

(E-01, E-04, E-10, E-22). A replacement must keep those, or the operator must
choose to lose them. `TODO/RULES.md` section 4 records the settled decisions

## NVIDIA/OpenShell at c4688aa8715e

### Pass 1: what it is

A gateway is the control plane. It keeps sandbox records in SQLite or an
external database, issues per-sandbox credentials and serves the CLI, a TUI
and SDKs. A compute driver builds each sandbox: Docker, Podman, Kubernetes, a
libkrun microVM, or Windows MXC. An extension driver can attach over a unix
socket (`docs/how-it-works/sandboxes/runtimes.mdx`, "Extension Drivers").
Each sandbox has two halves. The supervisor is on the trusted side: it holds
policy and credentials, resolves DNS and dials every approved connection. The
sandbox runtime, `openshell-sandbox`, runs inside the workload. It owns the
agent's process tree and hands each TCP open and DNS query to the supervisor
through seccomp user notification (`docs/about/architecture.mdx`).

An agent attaches as a command: `openshell sandbox create -- claude`, then an
SSH-based connect. There is no chat front end. Chat bots run inside one
sandbox: a Discord bot in #913, a Slack bot in #1107. Maturity: 0.1.x, a
stable release most weeks, fixes for the latest minor and the one before it
(`docs/about/support-matrix.mdx`). The gateway sends anonymous telemetry
unless `OPENSHELL_TELEMETRY_ENABLED=false` (`README.md`).

### The tracker

- **Refused or closed:** #113, a Docker daemon inside sandboxes, closed as a
  duplicate. No comment in the corpus names the original. #537, FUSE, not planned. #1393, a
  daemonless bubblewrap or Apptainer driver, not planned. #585, seccomp
  skipped in `Allow` mode: the triage found no managed path to it.
- **Host conditions that broke it:** #3417, kernels before 5.19, fixed by
  #3420 (merged 2026-09-22). #3842, the seccomp probe on WSL2. #3911, open,
  above. #4026, open. #1792, enterprise networks with a proxy as the only
  egress, fixed by #2245 (merged 2026-07-24).
- **The ruling worth keeping, from review:** #2245's first form read the
  proxy from the supervisor's environment. Review moved it to arguments that
  the driver sets, because a sandbox image can bake `ENV` values. The code
  says why at `upstream_proxy.rs:20-24, 372-377`. errand-box's proxy setting
  comes from `HTTPS_PROXY` at `up` (E-13). That is a host value, not a guest
  one, so the same rule holds there already.
- **Security reports:** #1169, DNS exfiltration through the resolution of a
  denied name, fixed by #1329. #1354, one shared secret for every sandbox, so
  any holder could act as any sandbox. The fix gives each sandbox and each
  generation its own tokens (`docs/about/architecture.mdx`). That is errand#49
  in another project, already paid for. #637, request smuggling through two
  `Content-Length` headers, fixed.
- **A number from a reporter, not measured here:** in #4406, at 96 open
  connections from one sandbox, new connections waited about 7.5 s on v0.1.3.

### Candidate verdicts, and the test of each

1. **Replaces errand-box and errand.** Refuted: no chat layer; the workload
   model removes Docker, systemd, FUSE and sudo; the drivers need cgroup v2,
   KVM or a cluster.
2. **Replaces errand-box's sandbox, for a rewritten errand.** Refuted on the
   target hosts: only the Docker driver remains on cgroup v1 without KVM, and
   its workload fails five of the nine guarantees above.
3. **Replaces errand's broker only.** Refuted: the supervisor depends on the
   gateway's tokens and on the in-workload runtime's seccomp mediation.
   Taking it is taking the architecture (research.md section 3.8).
4. **Adopt the upstream proxy chain into T-022.** Survives. The raw TCP path
   uses it (`proxy.rs:1248-1256`). It checks the policy generation just
   before the dial (`proxy.rs:1249`). It sends CONNECT to the validated
   address, so the proxy does no DNS of its own (`upstream_proxy.rs:302-315`).
5. **Adopt the generation guard into T-022.** Survives. `relay_tcp` is a
   plain two-way copy that one `select!` arm ends when the generation moves
   (`proxy/relay.rs:327-347`). errand-box's `relay::pump` (`src/relay.rs:14`)
   has no such arm.

**Verdict: adopt.** Without (1), T-022's relay fails on the hosts errand-box
targets, because egress there is a CONNECT proxy (E-10, E-22). Without (2), a
grant that the operator removes, or a session that is revoked, keeps its open
ssh connection.

## chika5105/raxis at 8e51824aa35c

### Pass 1: what it is

A kernel daemon admits Ed25519-signed plans from the operator, splits them
into tasks and runs planner agents (orchestrator, executor, reviewer) in
microVMs: Firecracker on Linux, Apple Virtualization on macOS. Each action is
an intent that the kernel admits or rejects. Every decision goes into a
SQLite store and a JSONL audit log. Per-session credential proxies (HTTP,
Postgres, MySQL, Redis, MongoDB, MSSQL, SMTP, cloud) keep secrets out of the
VM. A transparent proxy in the VM asks the kernel to admit each egress
(`crates/egress-admission/src/lib.rs:1-31`). The planners are its own
harness, not an external coding agent. Output to people is by notification
channel: shell, file, email and sidecar; Slack is planned for V3
(`specs/v2/email-and-notification-channels.md:19`).

Maturity: v0.1.0 on 2026-05-23 to v0.3.9 on 2026-07-14, last commit
2026-07-28. One copyright holder; contributions need a CLA (`README.md`). The
Linux x86_64 release archive is 788,506,118 bytes (`api/releases.json`).
Host needs: KVM and Firecracker, host cgroup v2, a guest kernel 5.14 or
later, systemd or launchd for daemon mode, 50 GB of disk
(`specs/v2/system-requirements.md:26-46, 81-83`).

### Pass 3: on errand-box's hosts

| host condition | result | evidence |
| --- | --- | --- |
| no KVM | the tier is `FallbackOnly`. With the unsafe flag it admits the Firecracker backend, which still needs `/dev/kvm` to boot a VM | `isolation-firecracker/src/lib.rs:252-276`, `src/vmm.rs:137` |
| cgroup v1 | host cgroup v2 is required | `specs/v2/system-requirements.md:83` |
| no init | foreground mode needs no supervisor | `system-requirements.md:43` |
| HTTP proxy only | no upstream proxy setting found; a provider it cannot reach fails every call | `system-requirements.md:383-404`; least-sure claim 5 |
| hosted container | refused by its own spec | `system-requirements.md:156` |

Every guarantee of errand-box's guest is moot here: raxis does not boot a
session on these hosts. On a host with KVM, the planner VM is raxis's own
image with its own harness. It is not a general guest with Docker for kage.

### The defect, and why it is kept

errand#44 and errand#47 cite raxis as a model. The files say what those
issues say. The code under them disagrees in three places:

1. **Check, then normalize.** `allows_path` is `path.starts_with(p)` on the
   raw request path (`restriction.rs:41-48`, called at `lib.rs:370`). No
   segment boundary: `/api/v1/widgets` admits `/api/v1/widgetsX`. Then
   `compose_target` hands the path to `Url::set_path` (`lib.rs:574-595`),
   which resolves `..` and `%2e%2e`. So the policy reads one path and the
   upstream gets another. The host stays pinned, so this is not errand#48's
   host rewrite. It is the same defect class one level down.
2. **The parse result is discarded.** `lib.rs:354-357` keeps the status only
   to drop it. A request that httparse refuses reaches the checks with the
   defaults `GET` and `/` (`lib.rs:359-360`).
3. **The path goes into the audit chain in plain text, beside its hash.**
   `lib.rs:639-640` and `credential-proxy-manager/src/lib.rs:587-595`. A
   token in a query string lands in the log. A failed audit write is logged
   and the request goes on (`credential-proxy-manager/src/lib.rs:596-608`).

**Its own tests missed it.** The path test (`restriction.rs:73-82`) tries the
prefix, one child and one unrelated path. It tries no sibling that shares the
prefix, no `..` and no encoded dot. The target tests (`lib.rs:720-737`) do not try a dot segment.

### Candidate verdicts, and the test of each

1. **Replaces errand-box and errand.** Refuted: KVM, cgroup v2, no chat
   session, its own agent, SSPL.
2. **Adopt the per-session proxy lifecycle into T-020 and T-023.** Partly
   survives: the started and stopped records are a good shape for T-023. As a
   revocation it is weaker than OpenShell's guard, because open connections
   outlive the shutdown (`lib.rs:1685-1692`). It is recorded above as an idea.
3. **Adopt the hash chain into T-023.** Refuted: unsigned, and errand-box's
   records are written by root, the party a chain would guard against.
4. **Anti-pattern exhibit for the broker.** Survives, read and not run.

**Verdict: anti-pattern exhibit.** The broker that replaces errand's must not
take raxis's HTTP proxy as its model for errand#44, #47 or #48.
